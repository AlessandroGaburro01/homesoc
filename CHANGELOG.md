### Fixed
- **SOC-01 disk full / `wazuh-agent` down for 2 days (`No space left on device`):** root cause was two-fold. (1) The Backblaze B2 offsite sync cron entry had been missing from root's crontab for ~9 weeks — never restored after the `backup-offsite.md` v1.2 runbook (April); the last B2 object predating this fix was from late April. (2) Local `vzdump` retention (`keep-last=3`, confirmed in `/etc/pve/jobs.cfg` — `backup-offsite.md` incorrectly documents "7", doc fix still pending) could not keep pace with dump sizes for `ct-102`/`vm-103`/`vm-105`; these three had been failing silently for 7–11 nights, masked because smaller VMs kept succeeding nightly. An orphaned LVM snapshot `snap_vm-102-disk-0_vzdump` (evidence of a mid-write failure) was removed. `wazuh-agent` on SOC-01 (ID 002) restarted and confirmed stable.
- **vm-103 / vm-105 IP drift ("phantom DHCP" on a statically-configured interface):** `/etc/netplan/50-cloud-init.yaml`, regenerated by cloud-init on every boot, carried `dhcp4: true` — depending on netplan's alphabetical merge order this either added a rotating secondary IP (vm-103) or fully overrode the static config (vm-105). Fixed on both hosts: `echo "network: {config: disabled}" > /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg`, removed `50-cloud-init.yaml`, `netplan apply`. Netplan config file permissions hardened to `600` on both (previously world-readable).

### Removed
- VM ID 200 (`gns3-vm`, Proxmox host — 4 vCPU/8GB RAM, 100G+1TB thin disks) — discovered undocumented during the backup audit above; never scoped via threat model or architecture docs. Removed (`qm destroy 200 --purge`) to keep the deployed environment aligned with the documented project scope, per the design-first principle (charter §8).

### Verified
- `wazuh-agent` on SOC-01: `active (running)`, stable post-restart, no reconnect loop
- `vm-103` / `vm-105`: `ip addr show ens18` shows a single static IPv4 with no secondary `dynamic` address, post cloud-init fix
- B2 (`rclone size b2-homesoc-crypt:`): 3 objects, 11.834 GiB total — one current copy each of vm-103/vm-105, plus one pre-existing orphaned `ct-101` object outside current scope

### Notes
- B2 total (11.834 GiB) sits slightly above the 10GB free tier, given the real size of the vm-103/vm-105 dumps — accepted knowingly; Backblaze overage cost at this volume is negligible (~$0.006/GB/month)
- `backup-offsite.md` still needs a doc-only update (retention is actually `keep-last=3`, not "7"; B2 cron is `04:30`, not `03:00`; B2 scope is now critical nodes only, not the full fleet) — not applied in this release
- Full ADR-05-01 rationale for the Fase 5/6 resequencing, including the RAM gate and the `LocalLLM_Triage_1_0` dataset rationale, lives in `docs/phase5-planning.md`
- No impact on Fase 0–4 deliverables — all changes in this release are infrastructure hardening plus a sequence-only roadmap change
